# 原型维护约定

修改本目录前阅读 README.md 和 工作流程.md。执行版本维护时读取项目根目录下 `.agents/skills/still-prototype-versioning/SKILL.md`。

- 最新开发基准由 README.md 指定；方案存档及 archive 不作为默认开发依据。
- 修改产品行为创建下一版本未定稿，不直接覆盖既有定稿。
- 修改产品原型的界面、样式、布局或交互行为时，必须在左侧「留白 · 交互方案」提供可操作的修改前后对比；辅助方案区自身的修改无需创建对比选项。
- 方案区只保留总标题、带序号的配置标题和可换行的 Tab 选项；完整规则遵循[修改未定稿与方案对比](工作流程.md#修改未定稿与方案对比)。
- 只有用户明确确认后生成定稿和配套资料。
- 不再维护命名表与命名图；用区域名称、定稿和版本迭代文档定位需求。历史命名资料冻结保留。
- 定稿清除未采用方案，保留真实产品状态；关键要求与验收条件写入版本迭代.md。
- 原型状态和原生实现／验收状态分开记录，未执行的检查不能标通过。
- 文档修订允许就地更正并记录；历史不明时标注未知，不补造定稿。
