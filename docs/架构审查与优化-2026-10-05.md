# 架构审查与优化 · 2026-10-05

本轮按稳定性与数据安全、性能、代码结构的顺序推进。审查以工作区现有 v1.8 实现为基线，保留原有未提交改动；不修改原型定稿、最低系统版本和已确认交互。

## 架构判断

这是一个适合保持单进程、单 Swift Package 的原生菜单栏应用。主线程上的可观察 Store 管理计时状态，SwiftUI 渲染面板，AppKit 管理菜单栏与浮动窗口；系统通知、辅助功能和登录项分别通过系统服务接入。无服务端和第三方运行依赖。

值得保留的设计：绝对截止时间避免计时累积漂移；测试可注入时钟和存档路径；版本化 JSON 使用原子替换；辅助功能缺失时仍可使用菜单栏；系统登录项状态作为事实来源；HTML 仅是设计依据。

主要问题集中在状态提交边界、运行轮次身份和周期工作，而非模块数量不足。继续维持单一构建目标，拆出纯数据、存储与提醒队列文件，便于独立验证。

## 保持的产品约束

- 轻提醒仍仅发送无声系统通知；通知未授权时不增加其他提示。
- 加时仍是独立 300 秒阶段；重置与“再来”恢复原定时长。
- 面板仍在打开时定位；显示中按方案 B 保持左边缘与顶部稳定。
- 退出/休眠期间到时，恢复后仍汇总轻提醒。
- 系统时间调整仍按墙钟解释，允许回拨后剩余时间大于原定时长。
- 登录自启仍由用户主动开启，辅助功能授权仍由系统管理。

## 后续工程边界

1. **系统场景验收**：macOS 14/15、多屏热插拔、全屏 Space、睡眠唤醒、系统通知权限变化和注销后自启，需要对应真实环境。编译通过不能替代这些验收。
2. **真实能耗测量**：本轮减少了可从代码及测试确认的多余工作，CPU、内存与耗电改善幅度仍需 Instruments 对比。不能从调用次数直接推算耗电百分比。
3. **辅助功能响应**：运行任务时仍采用受超时约束的轮询。若实测发现主线程卡顿，再把 AX 查询移到专用串行执行器或引入 AXObserver；应同时验证目标进程退出、Space 切换及授权变化。
4. **正式分发**：Release 构建已具备入口，开发者签名、公证、发布自动化及多实例运行策略仍需独立设计。未经分发决策，不引入自动更新或账户能力。
5. **数据恢复体验**：损坏或未知版本原文件继续保留，应用显示存储错误。选择备份、导入或重置数据属于后续产品流程；本轮不自动替换用户存档。

没有加入数据库、服务容器或通用插件层。应在出现多存储后端、明显 I/O 阻塞或更多窗口协调需求时，再用测量结果决定是否扩大架构。
