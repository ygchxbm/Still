# 2.0.1 胶囊权限兼容修订

日期：2026-11-19。原生系统兼容修复，保留 [v2.0 定稿](../prototype/v2.0/留白-v2.0-定稿.html)的任务及提醒方案。基于同日 2.0.0 实现继续修改；不重新定稿或修改历史 HTML。

## 依据与实现

Apple 于 2026-11-16 公布 [macOS 27.3 beta 2 权限调整](https://developer.apple.com/news/?id=oqng0zjk)，将普通跨 App 访问与无障碍辅助技术分开，并支持按目标 App 授权。具体操作参考 [Apple 新版授权说明](https://support.apple.com/en-us/149699)。

本机系统为 macOS 27.3，构建 26C5047e。读取本机 SecurityPrivacyExtension 的服务资源和本地化文案确认：

- `Privacy_Accessibility` 对应 **System & App Protection Override**，本机简体中文系统也使用英文名称。
- `Privacy_AccessibilityApps` 对应截图中的 **无障碍** 页面，其说明只供屏幕阅读器、语音控制等指定辅助技术应用使用。

据此使用系统设置 URL 打开 `com.apple.settings.PrivacySecurity.extension?Privacy_Accessibility`；未引入私有授权 API、授权数据库修改或辅助技术 entitlement。当前 Xcode SDK 为 macOS 27.2，使用既有公开 AX API与系统版本分流编译。

| 场景 | 处理 |
|---|---|
| macOS 27.3 及以后 | 按钮“设置胶囊权限”；直接打开 System & App Protection Override，跳过旧的 AX 授权提示。 |
| macOS 27.0–27.2 | 引导到设备控制与数据访问页面，保留原有授权请求。 |
| macOS 14–26 | 引导到辅助功能页面，保留原有授权请求。 |
| 设置 URL 打不开 | 尝试隐私与安全主页面；仍失败时提供手动设置提示。 |
| 全局信任为 false，但已主动设置胶囊 | 在 27.3 上尝试读取目标 App 的窗口，以实际结果处理局部授权。 |
| 拒绝、暂时无窗口或切换目标 | 分别呈现状态，隐藏不可定位的胶囊；显式拒绝后不逐秒重复访问。切回目标 App、切换 Space 或全局权限变化后重新检查。 |

仅把“用户主动设置胶囊的意图”保存到当前应用的 UserDefaults。这个标记不表示系统已授权；首次设置前，未获全局授权时不读取其他 App 窗口。重开后按实际窗口访问结果重新判断，不沿用之前的成功状态。

## 新版授权操作

1. 退出旧版，打开本次打包的 `Still.app`，在设置中点“设置胶囊权限”。
2. 在“隐私与安全 → System & App Protection Override”中点击＋，添加当前运行的 Still／留白。可展开“胶囊权限设置步骤”，用“在访达中显示留白”定位当前应用。
3. 选择“选取 App（Choose Apps）”，仅选择希望显示全屏胶囊的 App。如需自动检测，将所选 App 设为“At Any Time（随时）”；“Ask First”可能需要先回应系统询问。
4. 切回已允许的 App，开始倒计时并进入全屏，检查胶囊。新页面支持按 App 授权，不引导用户开启全局覆盖权限。

用途说明：留白仅读取前台窗口的全屏标志、位置、大小，不读取窗口内容，不发送键盘或鼠标操作。系统权限本身允许的范围可能大于留白实际使用的范围。
